# Vanessa Runner

Используй инструменты MCP-сервера `vanessa-runner`. Сначала проверь доступность нужных инструментов именно в текущем чате. Установка плагина и отдельный клиент из терминала этого не доказывают. При отсутствии MCP-инструмента сообщи ограничение; явно отличай возможный CLI-запуск от результата через MCP.

## Создать → открыть → проверить → закрыть

1. Для новой базы выбери отдельный каталог в разрешённой рабочей области. Проверь, что его ещё нет: `infobase_init` удаляет существующий каталог базы перед созданием. Никогда не используй init для повторного открытия.
2. Вызови `infobase_init` с явными `ibconnection` (`/F` и абсолютный путь), `v8version` и `nocache: true`. Если возвращён `taskId`, дождись `task_status` и прочитай `task_result`.
3. Вызови `run_enterprise` с `ibpath` (тот же абсолютный каталог) и `v8version`. Поддерживаются существующая файловая база Windows и тонкий клиент без аутентификации. Пустая база остаётся пустой; не называй её типовой конфигурацией.
4. Ответ `run_enterprise` может иметь `state: starting`: запуск принят, окно ещё не подтверждено. Запомни `runId` в контексте задачи. Читай `enterprise_status`, пока появится PID и нужное состояние. Не повторяй запуск при невидимом окне. `driverVersion: 0.3.1` подтверждает новую реализацию.
5. Для штатного закрытия вызови `enterprise_stop(runId, timeoutSeconds: 5)`. Плагин запрашивает закрытие собственных клиентов и менеджера. `close_pending` означает продолжающееся ожидание; смотри `processes`: PID, роль, заголовок окна, `responding`, `closeAccepted`, код выхода. Таймаут ограничивает ожидание ответа, процесс остаётся работать.
6. Завершение подтверждено только при `state: exited`, `cleanupStatus: exited`, `result: passed`. Для Vanessa также нужен `scenarioStatus: passed`. `scenarioStatus: passed` вместе с `result: cleanup_pending` означает выполненные проверки и незавершённое закрытие. Нулевой код менеджера этого не меняет.

## Vanessa: фоновая задача и управляемый запуск

Используй `test_vanessa` с явными `ibconnection`, `bddrunner-path`, `vanessasettings`, `workspace`, `v8version`, `nocache: true`, `background: true`. `taskId` появляется сразу. Через `task_result` прочитай строку `Vanessa runId: ...`; по этому UUID доступны `enterprise_status` и `enterprise_stop`. Не отправляй `taskId` вместо `runId`. `task_status/task_result` остаются доступны во время долгого сценария; общего дедлайна 300 секунд нет.

Управляемый запуск `test_vanessa` включён в Windows и macOS без `ibsrv`; другие режимы используют прежний запуск платформы. На Mac наблюдается собственная POSIX-группа процессов; подробности и ограничения — в `docs/mcp-local-setup.md`. Плагин учитывает потомков через Windows Job Object (`processTracking: windows_job`), поэтому выход промежуточного launcher не скрывает клиента. Перед объявлением завершения также проверь `activeProcessCount: 0`; одного вышедшего менеджера в `processes` недостаточно. Он не подключается к ранее открытым или удалённым клиентам и не принимает произвольные PID.

Состояние хранится в `%LOCALAPPDATA%/VanessaRunner/runs/<runId>/state.json`. Наблюдатель работает отдельно от MCP, поэтому этот runId можно проверить после переподключения под тем же пользователем на том же компьютере. Идентичность процессов закреплена удерживаемыми дескрипторами и временем создания. `supervision_lost/supervision_error` означает потерю достоверного наблюдения: не объявляй успех и не повторяй запуск автоматически. Старые runId версии 0.2.x не восстанавливаются. `taskId` фонового worker остаётся привязанным к текущему MCP; при переподключении используй уже полученный runId.

## Подготовка Vanessa Automation и диалоги

Перед запуском проверь фактические пути EPF, VAParams, feature, версию платформы и профили клиента. Для скриншотов нужна полная поставка с соответствующей VanessaExt. Официальный Single допустим; обычная сборка EPF из XML не подтверждает включение библиотек и нативных компонент. Не объявляй проверку комплектности выполненной только по наличию файла EPF.

Предупреждение безопасности не означает ошибку лицензии или зависание. Сначала установи причину по журналу регистрации 1С и состоянию собственного запуска. Не проси владельца диагностировать окно, если причина доступна в журнале. Не повторяй запуск поверх ожидающего.

В Windows используй `enterprise_authorize(runId, capability)` только для конкретной возможности (`open_processing` или `administer_users`) и обработки собственного запуска в разрешённом объёме. Если после `state: requested` платформа 1С показывает второе окно *«Текущее выполнение действия было прервано для выдачи предупреждения... Просьба сейчас вызвать действие еще раз»*, повторно вызови `enterprise_authorize` для того же `capability`: помощник закроет окно прерывания (`state: acknowledgement_requested`, `interruptedAction: true`, `requiresActionRetry: true`), после чего прерванное действие нужно выполнить повторно. В Windows и macOS для отдельных локальных тестовых баз предусмотрена явная идемпотентная подготовка `tools/macos-trusted-infobases.py`: сначала план без `--apply`, затем применение с `--apply --acknowledge-trust-change` только после согласия владельца на перечисленные базы (при необходимости путь к `conf.cfg` передаётся через `--config`). Подробности и отзыв разрешения (`--revoke`) — в `docs/mcp-local-setup.md`. Уже данное согласие на эти базы повторно не запрашивай. Не распространяй разрешение на другие базы и не подставляй общий шаблон `.*`.

После изменения останови прежний собственный запуск, проверь его завершение и выполни новый прогон. Изменение настройки не доказывает устранения проблемы: нужны свежий статус сценария и отчёт Vanessa. Отличай предварительную настройку окружения через CLI от действий MCP в текущем сеансе. Режим снимка 1 допустим; исправление режима 2 этой версией не заявлено.

Не создавай отдельные файлы отчёта о работе агента без запроса пользователя. Операционные файлы состояния создаёт сам плагин. Сборка и запуск не являются доказательством доступности инструментов в другом чате: проверяй их заново именно там. Не подменяй отсутствующие инструменты отдельным MCP-клиентом или мостом.

## Другие команды

- Выбирай инструмент по описанию. Версию платформы и существующие подключения получай из фактических данных среды; не угадывай их.
- Используй `nocache: true` и явное подключение для независимых баз: общий кэш может помнить другую цель. `cache_show` показывает текущие значения.
- Фоновые команды: сохрани `taskId`, проверь `task_status`, получи `task_result`. `task_cancel` отменяет фоновую команду; это не штатное закрытие предприятия.
- `debug: true` включает синхронный диагностический вызов; применяй при необходимости.

## Разрешения и отчёт

Создание, изменение базы и завершение запуска должны соответствовать явному запросу пользователя. Уже данное разрешение на конкретный сценарий повторно не запрашивай. Не обходи разрешения MCP-клиента, не трогай посторонние базы и процессы.

Сообщай реальные инструменты, состояния, код выхода и пути артефактов. Отличай доступность сервера, доступность инструментов в чате и фактически выполненный сценарий.

## Среда

Плагин запускает `src/mcp.os` через OneScript из корня пакета. Нужны зависимости Vanessa Runner и установленная платформа 1С. Управление окном Windows использует поставляемый `tools/enterprise-window.ps1`; помощник проверяет идентичность процесса и отправляет штатный запрос закрытия без принудительного завершения.

Если клиент обрезает каталог инструментов, используй поддерживаемый клиентом список `enabled_tools` из `docs/mcp-local-setup.md`. Не меняй глобальные настройки других проектов ради одной проверки.
